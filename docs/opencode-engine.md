# OpenCode instruction-engine contract

The engine accepts `handleAgentsChain('opencode', payload, options)` and the command entrypoint `node hooks/opencode.mjs`. This is instruction-only support for a consuming native plugin, not a standalone plugin or configuration import. The adapter owns tool translation, awaited model-visible context, successful-read evidence, session ancestry, retained context, resume, compaction, and runtime registration.

Use the established `session_id`, `cwd`, `hook_event_name: SessionStart | PreToolUse`, `source`, `tool_name`, and `tool_input` contract. Translate native file fields to `file_path`, `old_string`, `new_string`, and `content`; translate patch text to `command`, and use `Read`, `Edit`, `Write`, `Bash`, or `apply_patch`. Preserve the actual child session's instruction identity. Exit 2 returns an intentional first-write block with the rendered instructions; exit 0 may return JSON `hookSpecificOutput.additionalContext`. Internal collection errors remain fail-open and recorded without instruction text.

Pass `nativeInstructions: [{path, text, source?}]` to the function, or `native_instructions` in command JSON. Only exact observed text matching an eligible local user-owned regular `AGENTS.md` under the configured trusted roots seeds native delivery. Wrong-name symlink targets, excluded directories, remote paths, mismatched text, and inferred ancestors do not count. A native OpenCode read is not assumed successful before execution. Mark newly completed read evidence with `source: tool`; affected writes remain protected until the adapter marks that evidence `source: request` at the next ordinary model request. Evidence without a source preserves any existing recent-delivery protection. Evidence refreshes each call so changed disk contents without matching observed text are redelivered conservatively. Deduplication precedes filesystem collection, with retained evidence limited to 256 entries and 1 MiB of text.

The OpenCode delivery field cap is 32,000 characters and the shared epoch cap is 64 KiB. These are adapter limits, not upstream context-window claims. `SessionStart` with `source: resume` preserves the epoch only when the adapter has verified retention; `startup`, `compact`, or `clear` resets it. Supply `retainedContexts` as the full SHA-256 hashes of observed retained instruction-delivery text to validate coverage of the engine's emitted epoch. Missing coverage resets conservatively, including older state without delivery hashes. Native records are reseeded from fresh evidence at session start. The command entrypoint accepts this list as `retained_contexts`. If context retention is unknown, the adapter must reset rather than suppress instructions based on stale storage.

Engine fixtures and archive-install checks cover identity, exact evidence, exclusions, first-write and same-batch retries, changed instructions, independent child epochs, resume/reset, capped outlines, and reporting. They do not establish native plugin delivery or model instruction-following. The [historical V1 assessment](opencode.md) covers OpenCode 1.18.19; consuming adapters must verify their own installed runtime, including OpenCode 1.19.5, instead of treating those historical probes as current evidence.
